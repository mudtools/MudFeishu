
# 能力出处与元工具（feishu.*）

## 路由优先级（先判断对象属于哪个域）
- 「这个能力有没有」→ `feishu.capability_lookup`；「这个域怎么用、有哪些坑」→ `feishu.guidance_read`。
- 这两个是**元工具**：它们不执行任何业务动作，只回答「有没有 / 怎么用」，
  真正做事仍要回到对应业务域的工具。

## 前置链
能力不在工具集 → `feishu.capability_lookup`；要某域深层避坑 → `feishu.guidance_read(domain, topic)`。
先 `guidance_read` 再重试，是「同一工具连续失败」的正确下一步。

## 避坑
- `capability_lookup` 只回元数据，**不代表能调用**。
- 它报「能力存在但未策展」时**如实告知，禁止臆造 API 调用**。
- `guidance_read` 的键是 `{域}/{主题}`；键不存在时会**列出全部候选键**，从清单里选，不要自行拼造。
- 两个工具都只回编译期常量，**不发起任何飞书请求**（无租户/身份风险）。

## 安全规则
- 本域全为只读元工具（无写操作、无 `dry_run` 语义）。
- 不得把「能力存在」当成「已启用」向用户承诺；两者差一个白名单。
- 只使用本域真实工具名，不臆造不存在的工具或 API。

## 示例
能发卡片吗 → `capability_lookup` → 如实告知结果。
