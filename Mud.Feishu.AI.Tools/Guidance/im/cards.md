
# IM：交互式卡片消息

## 前置链
1. `im.send_card` 需要接收方与 `receive_id_type`——与 `im.send_message` 同口径（推荐 open_id）
2. `body` 与 `buttons` 用**结构化语法**描述（不是 JSON）

## 语法
- `body` 每行一个元素：`text:内容` / `quote:内容` / `code:内容` / `divider`
- `buttons` 每行一个按钮：`按钮文本|url|https://…` 或 `按钮文本|value|回调值`

## 避坑
- **不要写 JSON**：把卡片 JSON 塞进 body 不会被解析成卡片，只会当一行纯文本发出去。
- 卡片是**单向外发**：按钮点击由宿主的回调端点处理，工具链里拿不到点击事件，
  因此不要把卡片当成"等用户点完再继续"的同步交互。
- 通知 / 待办 / 审批提醒优先用卡片（要点一眼可见、能直接点按钮）；长篇正文仍用 `im.send_message`。
- 卡片不带附件：需要图片或文件时改用 `im.send_image` / `im.send_file`。
- 写操作默认空名单不启用，启用前须经宿主授权。

## 示例
- 「把这个待办发给张三」→ 卡片 body：`text:标题` + `quote:截止时间` + 按钮 `查看|url|https://…`。
- 「让对方直接确认」→ 按钮 `value` 形式，由宿主回调处理确认动作。
