# ADR-0002：域 guidance 总长预算（常量取值与其历次复算记录）

- 状态：**生效中**（常量取值随域资产增长复算，本文件同步更新）
- 日期：2026-10-14（由 `FeishuGuidanceBudget` 的类注释迁出；测量数据为历轮实测值）
- 影响面：`Mud.Feishu.AI/Agents/FeishuGuidanceBudget.cs`，
  `Mud.AI.Agent/Guidance/GuidanceComposer.Compose(..., maxGuidanceLength)`

## 背景

域 guidance 资产（每个 L1 域一节）在装配期拼接进模型指令。装配器（中立包）只接收
`maxGuidanceLength` 参数；**预算数值本身是产品语义**，留在飞书侧。
超限策略是**整域丢弃**且失败方式静默（仅装配结果上的 `Truncated` / `OmittedDomains` 可查）。

## 决策

1. 预算是**常量**而非配置键：每个公开配置属性都必须有真实消费点与守卫登记，当前没有第二个取值需求。
2. **额度只计域 guidance 本体**（含块间分隔符），**不含**宿主 `Instructions`——
   宿主指令长度不该决定域资产是否被注入。
3. 恒定流程：**内容加长 → 先复算总量 → 再抬常量**（禁止先抬常量再写内容）。

## 常量演进（每次复算的实测依据）

| 轮次 | 取值 | 依据（实测） | 失败形态（若维持旧值） |
|---|---|---|---|
| 初值 | 2048 | 按「中文 UTF-8 3 字节/字符」估算：把 6,578 **字节**当成 ≈2,030 **字符** | 14 域合计 ≈3,624 字符 + 13 分隔符 ≈3,650，**超预算 78%** ⇒ 第 7 个域起共 8 个域的 guidance 从未进过 prompt |
| R5 / B-12 | 8192 | 8192 > 3,650 ⇒ 全域零丢弃 | — |
| R6 / S1 | 16384 | 每域从三节扩为五节（新增「路由优先级」「安全规则」），16 域实测 **12,836** 字符（余量 ≈27%，约 4 个新域） | 尾部域静默整域丢弃——"深化了内容却一域都进不了 prompt" |
| R7 / A4~A6 | 24576 | 新增 Board / Attendance / Spark 三域共 4,629 字符（1,286 / 1,576 / 1,767），20 域实测 **20,079** 字符（余量 ≈22%） | 尾部域（按启用工具数降序）整域丢弃 |
| F-1 | **32768** | 新增 `mdm` ≈1,579 + `security` ≈1,901，23 个 L1 资产合计 **≈25,209** 字符（余量 ≈30%，≈4 个新域） | 尾部域整域丢弃 |

单域上限 2048（每域 ≤ 2 KB 的结构化改造余量）不受本常量影响。

## 后果

- 装配器不持有任何产品预算；换产品/换域集只改本常量（以及本文件的复算表）。
- 守卫 `GuidanceAssetContractGuards` 的「全域拼装零丢弃」用例锁死该不变量：
  **再加长 md 会立刻报红**，迫使常量与内容长度同批评审。
