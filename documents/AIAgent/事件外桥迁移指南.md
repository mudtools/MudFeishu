# 事件外桥迁移指南（进程外 Agent 消费飞书事件）

> 决策依据：[ADR-0005](decisions/ADR-0005-event-bridge-disposition.md)（DP-1 = 维持 Demo 参考实现）。
> 适用读者：需要把飞书事件交给**仓外进程**（另一台机器上的 Agent、消息队列、批处理、文件 tail 的
> 外部消费者）的宿主。

## 0. 一句话结论

**NDJSON 事件外桥不在 NuGet 发布面**。要让仓外 Agent 消费飞书事件，唯一受支持的路径是
**复制 Demo 的参考实现到你的工程**，并把它挂在宿主的事件出口上。库本身**不做 IO**，因此不会
替你落盘/转发。

## 1. 为什么不在库里

R-10 把外桥与事件目录（共 37 条公开面）从 `Mud.Feishu.AI` 移出，落点
`Demos/Mud.Feishu.Agent.Demo/Events/`。理由：外桥是「把事件交给仓外进程」的**产品主张**，
而库本身不做 IO；留在发布面等于承诺一条**无人验证**的路径。库保留的是**进程内**能力
（WebSocket/Webhook + 会话式事件处理），它不解决「事件如何离开进程」。

## 2. 三种落地路径

| 路径 | 适用场景 | 状态 |
|---|---|---|
| **A. 复制 Demo 实现** | 事件必须交给仓外进程（外部 Agent / MQ / 文件） | ✅ **唯一受支持路径**（本指南） |
| **B. 进程内闭环** | 宿主本身就是 .NET，事件→模型→回复全在进程内 | ✅ 用 `ConversationalFeishuEventHandler`，**无需外桥** |
| **C. MCP 事件资源化** | 远程 MCP 客户端订阅事件流 | ⏳ **未交付**（待 MCP HTTP 通道落地，随 ADR-0005 升级） |

> 若你的宿主已是 .NET 进程且只需要「事件 → 模型 → 回复」，走路径 B，不要引入外桥——
> 外桥的意义只在「事件要离开当前进程」时才成立。

## 3. 复制步骤（路径 A）

### 步骤 1：复制两个文件

把这两个文件复制到你的工程（命名空间自行调整）：

- `Demos/Mud.Feishu.Agent.Demo/Events/FeishuEventNdjsonBridge.cs`
  （含 `FeishuEventEnvelope` / `IFeishuEventSink` / `IFeishuEventFileRouter` /
  `FeishuEventNdjsonBridge` / `RegexEventFileRouter`）
- `Demos/Mud.Feishu.Agent.Demo/Events/FeishuEventCatalog.cs`
  （事件键清单，用于**写对路由正则**——写错正则的表现是**静默不落盘**）

这两个文件**不依赖 Demo 的其它代码**，只依赖 BCL 与 `Mud.Feishu.EventCallback`
（`FeishuEventCatalog` 读取 `FeishuEventTypes` 常量）。

### 步骤 2：挂到宿主的事件出口

库通过 `IFeishuEventHandler` 分发事件（`DefaultFeishuEventHandlerFactory` 由 DI 里的
`IEnumerable<IFeishuEventHandler>` 构造）。写一个处理器，在 `HandleAsync` 里把事件塞进外桥：

```csharp
using Mud.Feishu.Abstractions;
using Mud.Feishu.Abstractions.EventHandlers; // GetEventRawJson

internal sealed class NdjsonBridgeEventHandler(FeishuEventNdjsonBridge bridge) : IFeishuEventHandler
{
    // 空字符串 = 接收全部事件类型（见 DefaultFeishuEventHandlerFactory 的匹配语义）
    public string SupportedEventType => string.Empty;

    public Task HandleAsync(EventData eventData, CancellationToken cancellationToken = default)
        => bridge.WriteAsync(
            new FeishuEventEnvelope(
                EventKey: eventData.EventType,
                PayloadJson: eventData.GetEventRawJson() ?? string.Empty,
                EventId: eventData.EventId),
            cancellationToken).AsTask();
}
```

注册（WebSocket / Webhook 装配后）：

```csharp
services.AddSingleton(sp => new FeishuEventNdjsonBridge(
    output: null, // 只走路由落盘；要看 stdout 就传 Console.Out
    router: new RegexEventFileRouter(
        outputDirectory,
        ("^im\\.", "im"),
        ("^approval\\.", "approval"),
        ("^task\\.", "task"))));

services.AddSingleton<IFeishuEventHandler, NdjsonBridgeEventHandler>();
```

> **载荷口径**：`EventData.Event` 自 R-E1 起统一为 **JSON 原文字符串**，
> 读取一律经 `GetEventRawJson()`（它同时兼容历史 `JsonElement` 形态）。
> 外桥**原样嵌入**该文本、不做二次序列化——这正是「字段不丢、零 AOT 反射破口」的来源。

### 步骤 3：处理互斥闸门

**同一事件不得既进模型（会话处理器）又外桥**——两侧各自产生副作用（发消息 / 落文件），
重复消费极难察觉。外桥默认提供**机械互斥检查**：

```csharp
// 只外桥、不做会话处理：无需任何放行。
// 两者并存：必须显式声明互斥依据，否则抛错。
FeishuEventNdjsonBridge.AllowConcurrentWithConversational(
    "事件面不重叠：im.* 走会话，approval.* 走外桥");
```

`EnsureNotConversational(conversationalHandlerCount)` 是同一个闸门的显式检查入口。

## 4. NDJSON 格式（消费方契约）

一行一个 JSON 对象：

```json
{"event_key":"im.message.receive_v1","app_key":"cli_xxx","event_id":"evt_xxx","received_at":"2026-10-16T08:00:00.0000000+00:00","payload":{ … 原始事件载荷 … }}
```

- `payload` 是**原始文本原样嵌入**（不是二次序列化）——消费方自行选型解析；
- `app_key` / `event_id` 仅在非空时出现；`received_at` 缺失时由外桥填 UTC 当前时刻；
- 载荷非法 JSON 或路由落盘失败 ⇒ **抛错**（外桥丢事件是最难发现的故障形态，宁可当场失败）。

`RegexEventFileRouter` 的落盘形态：`{根目录}/{事件键清洗}.ndjson`，**追加写**（历史不被截断，
`tail -f` 与重放都可用）。正则按声明顺序取**首个命中**；未命中即**不落盘**。

## 5. 消费方建议

- **按行读**（NDJSON 的换行是记录边界）；不要按文件读全量（文件是追加增长的）。
- **幂等**：跨进程没有库的去重器，消费方应据 `event_id` 自建幂等（外桥不替你判重）。
- **正则核对**：路由正则写错 = 静默不落盘。用 `FeishuEventCatalog.ListEventKeys()`
  取权威事件键清单，或在接入时对落点做一次断言（Demo 就是这么做的：
  写 N 条 ⇒ 目录下必须有对应 `.ndjson`）。

## 6. 版本与兼容

外桥是 **Demo 参考实现**，随 Demo 演进，**不在 semver 承诺内**。复制后即由你的工程自行维护；
库升级（如 `EventData` 形态收敛）时按本文档的迁移提示调整即可。若需要「库级承诺 + 长期兼容」的
事件外送通道，属于 ADR-0005 的升级范围（路径 (a) 或 (c)），须先走决策，不要自行把外桥塞回
发布包。
