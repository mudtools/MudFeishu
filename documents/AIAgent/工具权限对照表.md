WP2 后契约守卫**不再内嵌手抄 scope 期望表**：本表的工具名列与 RequiredScopes 列由
`PermissionMappingDocContractGuards` 与编译期类型化契约（`FeishuToolContracts`，生成器从

> **关于"权威性"的说明（R4/WP2 更新）**：代码侧 scope 的唯一真相源是生成器（编译期契约），
> 本表是它的人读视图（一致性由守卫锁定）；scope 名是否为真实权限点，由
> `scope-authority.json` 收敛——每个条目须登记核对来源，未核对项以 `⚠️` 显式标记并持续出现在守卫输出中。

## 写工具的安全面（R3/AT-F13 + R4/T4-1）

- 全部写工具均支持 `dry_run=true`：**不调用下游**，只返回将要下发的 method/path 与请求体字段摘要
  （摘要只回字段名与长度，不回原文——否则预演会成为绕过出站净化的回显通道）；
  `dry_run` 时幂等键**不消耗**（摘要显式回显 `idempotency_key` 的 provided/omitted）。
- **幂等键（`idempotency_key`）已落地（R4/T4-1，零 SDK 改动）**：五个写工具统一以同名参数
  `idempotency_key` 暴露，落点由各 SDK 既有能力承担——
  `bitable.add_record` → 查询参数 `client_token`；`im.send_message` / `approval.create_instance`
  → 请求体 `Uuid`；`calendar.create_event` → 查询参数 `idempotency_key`；
  `task.create_task` → 请求体 `ClientToken`。
  三种失败语义不同（模型可见契约已写明）：Bitable 重复请求**返回原记录**；
  IM `Uuid` 在 **1 小时窗口内静默去重**；Approval `Uuid` 冲突**报错 60012**；
  省略即不保证幂等，且幂等键**不跨工具共享**。
- **附件上传的两道前置件（R4/WP7）**：① 参数只接受 `image_url`/`file_url`（**不接受本地路径**——
  模型给本地路径是危险信号，直接 `invalid_args`）；② 落盘由宿主实现 `IFeishuAttachmentStager`
  （域名白名单/大小上限/MIME 校验属宿主安全域），**未注册该接口时两个上传工具不注册**（软缺席）；
  临时文件经 `Cleanup` 在 `finally` 中清理（不进 GC/finalizer）。工具数因此不随宿主环境变化而"少注册"，
  而是**明确不暴露**。
- **HITL 确认（WP3 后）**：授权器返回 `NeedsUserConfirmation` 时，SDK 执行链**中性拒绝**
  （不签发任何凭据），只经 `IFeishuToolApprovalChannel` 通知宿主（携带参数摘要）。
  批准状态所有权归宿主授权器（`IToolExecutionAuthorizer`）——宿主批准后下次同 `(tool, argsDigest, appKey, userId)`
  调用返回 `Allowed`。未注册通道时降级为纯提示文案（fail-closed）。

- **board**：`DownloadWhiteboardImageAsync`（画板缩略图）——返回 `byte[]` → 二进制防线。
- **minutes**：`GetMinuteTranscriptAsync`（妙记逐字稿原文）——长文本 + 二进制附件通道；结论/待办经 `minutes.get_artifacts` 已覆盖。
- **drive**：（2026-10-16 T-1 更新）评论/权限面已策展；**下载通道已从"不在工具面"改为受控出口**——`drive.download_file`（资源文件）与 `drive.export_document`（云文档导出）经宿主 `IFeishuAttachmentStager` 落盘，字节不进模型上下文。**仍有意不策展**：版本管理面（`CreateFileVersionAsync` / `GetFileVersionPageListAsync` / `DeleteFileVersionByFileTokenAsync` 等）与导入任务面（`CreateImportTaskAsync` / `GetImportTaskAsync`）——前者与受控下载同族但低频，后者与导出成对但依赖 `[FormContent]` 上传链。

## 宿主授权消费约定

- 只读工具默认放行（未注册授权器时），scope 仅供审计；
- **策略轴（R3/AT-B13）**：`FeishuAgent:MaxToolRisk`（默认 `high-risk-write`）与
  `FeishuAgent:AllowedIdentities`（默认 `["tenant"]`）在**授权门禁之前**判定，
  拒绝时零调用下游、不切租户，审计 `reason` 以 `policy_denied: {reason_code}` 开头
  （reason_code ∈ `risk_exceeded` / `identity_mismatch` / `tool_not_allowed`）；
- 写类工具：`EnforceToolAuthorization=true`（默认）时必须注册 `IToolExecutionAuthorizer` 且判定
  `Allowed` 才会调用下游——安全默认不削弱（总体设计 §7.2）；
- 宿主 SIEM 经 `IToolExecutionAuditSink` 订阅 `RequiredScopes` 字段做权限审计（拒绝路径亦投递）。

## 维护约定

- 平台侧权限点变更（拆分/下线）时，本表与 `FeishuToolContractGuards` 中的 scope 期望表**同批更新**
  （守卫期望表集中一处，单点更新）；
- **新增/删除工具时，本表与守卫的期望表必须同批更新**——由
  `PermissionMappingDocContractGuards.PermissionDoc_ShouldCoverExactlyAllContractTools` 机械断言
  （工具名集合不等即红）；
- 每次扩容新工具，其 scope 核对为该工具 DoD 的一部分；
- ⚠️ 项在控制台核实后更新为 ✅ 并在「核对日期」处追加记录。
