# 工具错误契约

工具失败时，消费方（宿主与模型作者）读到的是本文档，不是源码。本文档由
`Tests/Mud.Feishu.AI.Tools.Tests/ContractGuards/ToolErrorDocContractGuards.cs`
机械守护：文中两份闭集清单与代码闭集**逐一相等**（防文档漂移）。

精简内联版见 MCP 资源 `feishu-errors://contract`
（`FeishuMcpResourceCatalog.ErrorContractSummary`），其闭集由
`McpResourceContractGuards.ErrorContractSummary_ClosedSets_ShouldMatchCodeClosure` 与代码闭集对齐；
本文档是**完整版真相源**（字段表 / 生产者纪律 / 版本演进规则）。

## 1. 载荷形态

工具失败时，结果文本的**第一行**是一行紧凑 JSON（≤ 512 字节，`MaxPayloadBytes`）：

```json
{"tool_error":{"category":"retryable","subtype":"rate_limited","retryable":true,"retry_after_seconds":3,"api_code":99991400,"attempts":2,"trace":"a1b2c3","tool":"mail.list_messages","suggestions":["…"],"required_scopes":["…"]}}
```

第二行是 `[next] ` 恢复提示（一行处置指引），其后是人类可读正文。

| 字段 | 类型 | 语义 | 出现条件 |
|---|---|---|---|
| `category` | string | 8 类闭集（见 §2），**恒在** | 恒在 |
| `subtype` | string | 细粒度原因码（见 §3），**恒在** | 恒在 |
| `retryable` | boolean | 该错误是否值得重试 | 恒在 |
| `retry_after_seconds` | integer | 建议等待秒数 | 仅可重试类有产出点时（E-5） |
| `api_code` | integer | 飞书业务错误码 | 有码时 |
| `attempts` | integer | 已尝试次数 | 有重试链路时 |
| `trace` | string | 追踪号（报告/排查用） | 有时 |
| `tool` | string | 产出错误的工具名 | 恒在 |
| `suggestions` | string[] | 恢复候选（码表/参数合法值） | 有事实来源时；**无来源不产出空数组** |
| `required_scopes` | string[] | 工具声明的所需权限（不是"平台缺什么"的结论） | 仅授权拒绝（E-1） |

降级纪律（预算单向上界）：候选与 scopes 可被丢弃，**分类字段（category/subtype/retryable）恒在**——没有分类，建议也无从解读。

## 2. Category 闭集

8 类，与 `ToolErrorCategory` 枚举经 `FeishuToolBinding.CategoryLiteral` 的映射逐一相等：

### Category 闭集

```text
# 8 类闭集；新增需评审并同批更新：枚举 / 本清单 / MCP 摘要 / 本文决策树
validation
policy
authorization
confirmation
retryable
api
internal
content_safety
```

- `validation`：参数验证失败——模型应换参数而非重试。
- `policy`：策略拒绝（风险/身份/白名单）——确定性失败。
- `authorization`：授权拒绝（授权器拒绝 / 缺 scope）。
- `confirmation`：待用户确认（HITL）——既非权限被拒也非参数错。
- `retryable`：可重试（HTTP 5xx / 429 / 网络异常 / 99991400）。
- `api`：飞书业务错误（code ≠ 0 且非权限段位）。
- `internal`：内部错误（未预期异常）。
- `content_safety`：内容安全阻断。

## 4. 分类来源（生产者纪律）

| 来源 | 判定 | 结果 |
|---|---|---|
| 异常类型 | `ArgumentException` → validation/invalid_args；`HttpRequestException` → retryable/transient；`TimeoutException` → retryable/timeout；其余 → internal/unexpected | `ToolErrorClassifier.Classify` |
| HTTP 状态 | 401/403 → authorization/authorization_denied；429 → retryable/rate_limited；≥500 → retryable/transient；其余 → api/upstream_error | `ClassifyHttpStatus` |
| 飞书业务码（**在飞书侧读表**） | 99991663/99991661 → authorization/authorization_denied；99991400 → retryable/rate_limited；**未收录的码一律 api/upstream_error，不猜语义** | `FeishuApiErrorVocabulary.Classify`（读数经 `ToolApiFailure` 传入中立层） |

- HTTP 状态码经**产品中立端口** `ITransportFault`（`Mud.AI.Abstractions.Tools.Errors`）由产品适配层供给
  （飞书侧 = `FeishuTransportFaultAdapter`，把 `Mud.HttpUtils.ApiException` 投影为状态码）：
  中立的错误分类器**不得认识任何具体 HTTP 组件的异常类型**（独立产品线纪律）。漏接适配时传输异常会落到
  `HttpRequestException` 兜底（retryable/transient），403 将被误判为可重试——故有端到端用例
  （`ToolErrorContractGuards` 的传输异常分类断言）锁定该接线。

- `suggestions` 只在有事实来源时产出：产品码表（飞书侧 `FeishuApiErrorVocabulary`）命中给"语义 + 行动"；
  未收录的码**不得**猜测。码表在**产品侧**（独立产品线纪律）：业务码读数经 `ToolApiFailure`
  （`Mud.AI.Agent.Tools`）随解包结果传入中立层，由 `FeishuApiResultReader` 在产品侧填好——
  端到端接线由 `ToolErrorContractGuards.ApiCodeReading_ShouldTravelFromReaderToPayload` 锁定
  （漏接即静默退化成 `api/upstream_error`）。
- 策略拒绝的 reason 文案带子类前缀（如 `domain_not_allowed: …`），正文与载荷同源。
- 全部执行器错误路径必经唯一出口（`ToolResultPipeline.Error` → `ToolErrorPayloadSerializer.Serialize`），由 `ToolErrorContractGuards` 金丝雀守护。

## 5. 消费者决策树（模型视角）

- `category = validation`：按 `suggestions` 修正参数后重试；不要原样重试。
- `category = policy`：宿主策略禁止，确定性失败——放弃该工具或改用只读方案，不要重试。
- `category = authorization`：把 `required_scopes` 如实转告用户/宿主申请权限；`subtype = user_auth_required` 时转告用户完成飞书授权，不要换工具或重试。
- `category = confirmation`：等待用户确认后再发起，不要自行重复调用。
- `category = retryable`：按 `retry_after_seconds` 等待后重试同一调用；无该字段时短暂退避。
- `category = api`：命中码表按码表行动；未命中则核对参数与对象可见性，如实报告（附 `api_code`/`trace`）。
- `category = internal`：如实报告用户并附追踪号，不要臆造结果或重试。
- `category = content_safety`：放弃该结果，不要改写参数重试。

## 6. 版本演进规则

- 两份闭集**只增不改**：字面量一旦对外发布即为承诺，改名 = 破坏性变更。
- 新增 subtype 必须同时满足：有真实产出点（幽灵子类守卫 `ToolErrorSubtype_Constants_ShouldAllHaveProducers` 会拦截）、同批更新本文档闭集与 MCP 摘要（两个守卫机械相等）、更新决策树处置。
- 删除 subtype 前先删产出点，并移入 §3 的 N/A 登记表。
