# 上游契约适配史

记录本仓为适配上游 `Mud.HttpUtils` 契约变更而做的决策**理由**。源码注释只保留"当下必须怎样"，
"为什么必须这样"。本文承接从源码中移出的适配史。

---

## 1. 带 appKey 的切换入口：默认拒绝语义

**适配点**：`IAppAccessAuthorizer` 未注册时，带 appKey 的切换入口由「静默放行」改为「默认拒绝」
（调用时抛 `InvalidOperationException`）。

**涉及入口（守卫口径一致）**：

- 生成类的 `UseAppScope(appKey)`
- 本 SDK 内部多应用切换入口 `IAppContextHolder.SwitchToApp(appKey, appManager, sp)`
  （原经 `FeishuAppManager.GetWebApi` 转达；该成员已于上游 3.0.8 移除批次中删除）

**默认授权器**：由放行型升级为「注册表白名单」语义——谓词经 `IFeishuAppManager.HasApp` 动态判定，
`AddApp` 运行时新增的应用即时获得授权。宿主可先注册更严格的 `IAppAccessAuthorizer` 实现
（`TryAdd` 语义：先注册者胜出）实现租户级授权。

**注意**：该判定是**静态的、不感知调用主体**。`appKey` 来源于外部请求参数时，宿主必须替换为
绑定主体的授权器。

---

## 2. `IAppContextHolder`：默认持有器与自定义持有器的两条边界

本仓注册点保留 `AsyncLocalAppContextSwitcher` 为默认持有器。

宿主自定义 `IAppContextHolder` 时，上游委托式适配器（`DelegatingAppContextHolder`，
用于按需包裹已有持有器）有两条边界：

1. `Current` 初始为 `init` 值（不可空），适配器**不支持**对初始持有器做写入适配；
2. 自定义持有器必须为单例，且须在**首次访问应用上下文之前**完成注册——晚于首次访问，
   适配器已固化为默认实例。

---

## 3. 弹性策略解析器：必须读当前配置而非注册期快照

选项工厂读取 `IOptionsMonitor` 的**当前**值，而不是注册期快照 `configs`。

理由：否则配置热更新后新增的应用永远拿不到 per-app 弹性策略，只能落到全局回退。

解析器内置配置变更订阅（策略指纹 diff 失效缓存，无需进程重启）；per-app 命名客户端不参与
全局 client 缓存指纹，因此弹性参数热更新不会被连带失效。

---

## 4. 令牌恢复选项：走组件官方绑定入口，不自行绑定 `TokenRecoveryOptions`

`TokenRecoveryOptions.TokenInvalidationDetector` 是**接口类型**的扩展点（编程式注入面）。
直接 `Bind<TokenRecoveryOptions>` 会在本编译单元产出无法抑制的 `SYSLIB1100` / `SYSLIB1101`
（绑定源生成器无法静态分析接口成员）。

**处置（组件 3.0.9 起）**：注册入口统一调用
`AddMudHttpTokenRecoveryFromConfiguration(configuration)`。该入口把绑定面收敛为纯 DTO 投影
`TokenRecoveryConfiguration`（仅基元/字符串/枚举成员）再经 `Apply` 逐字段映射，反射绑定以带理由的
抑制收敛在组件内部、不流向下游编译单元；同时显式挂接配置变更令牌源（热更新闭合）、注册
`TokenRecoveryOptionsValidator` 与可直接解析的 `TokenRecoveryOptions` 实例。
**不得**再在飞书侧重写 DTO 投影 / `Apply` / 手工 `IOptionsChangeTokenSource`。

另注：仅调用 `AddOptions<T>()` **不会**绑定任何配置节；`"MudHttpTokenRecovery"` 节会被静默忽略，
`TokenRecoveryOptions` 永远取默认值——这正是必须走官方绑定入口的原因。无 `IConfiguration` 的
代码式注册路径保留只注册选项管线与校验器/可解析实例（不含节绑定）。

---

## 5. `IFeishuAppContextSwitcher`：三个无作用域切换成员为何必须保留

上游 `IAppContextSwitcher` 已移除 `UseApp(string)` / `UseDefaultApp()` / `BeginScope(string)`，
生成器也不再默认发射它们。本仓接口**显式重声明**这三个成员：

- 目的：维持 `Mud.Feishu` 的对外契约与既有的生成实现类（188+ 个）兼容。
- 硬约束：三个成员的**签名必须与上游 `IAppContextSwitcher` 原签名逐字一致**。
  签名一旦不匹配，上游的"自声明 ⇒ 豁免"机制失效，生成器不再豁免，实现类会落入契约补全，
  产出 `HTTPCLIENT024` 与 `NotSupportedException` 占位实现。
- 契约守卫：`GeneratedAppSwitchContractTests`（`Tests/Mud.Feishu.Tests`）以反射方式对所有
  生成类断言这五个切换成员。
- 何时移除：**不得**在下一个大版本之前删除。
- 新代码应改用 `IAppScopeSwitcher.UseAppScope` / `UseDefaultAppScope`；需要"受控切换并保持"语义时用
  `IAppContextHolder.SwitchToApp(appKey, appManager, sp)`。
