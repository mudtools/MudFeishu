# 迁移与弃用史

`[Obsolete]` 消息只写「改用 X + 一句理由 + 移除版本」（规范 §4 模板，≤ 80 字）。
**何时弃用、为什么弃用、历次签名变化**记在本文件。

模板：

```
改用 <新成员/新路径>：<一句理由（≤ 30 字）>。将在 <大版本> 移除。
```

> 移除动作（分阶段清单、门禁同步、与上游的共释锚点）见 `弃用成员移除方案.md`。
> 本文件只记录弃用史，不承载移除排期。

---

## `IAppManager<T>.GetWebApi` / `GetDefaultWebApi` —— **已移除（3.0.8）**

- **弃用方**：上游 `Mud.HttpUtils` 3.0.7（`BC-30`），3.x 编译告警，**3.0.8 物理移除**。
- **本仓处置**：`FeishuAppManager` 的两个重写曾**同步传播** `[Obsolete]`（消除 `CS0672`），
  使经 `FeishuAppManager` 调用的消费方同样获得迁移指引；3.0.8 同批**已随上游删除这两个重写**
  （以及 `RegisterSwitcherFactory` 的遮蔽与显式实现）。
- **迁移路径**：
  1. DI 解析 `IAppScopeSwitcher` + `UseAppScope(appKey)` / `UseDefaultAppScope()` —— 自动归还上下文；
  2. `IAppContextHolder.SwitchToApp(appKey, appManager, sp)` —— 受控切换并保持，与原方法语义等价。
- **移除纪律**：「引用升级到 3.0.8」与「删除本仓实现」**必须同批落地**，否则会静默回落到基类
  **无授权守卫**实现（安全事故，非编译错误）；详见 `弃用成员移除方案.md` §2 档 A。

## `IAppManager<T>.RegisterSwitcherFactory` —— **已移除（3.0.8）**

- 同上属 `BC-30` 的弃用族；上游 3.0.8 物理移除基类工厂委托路径，本仓的 `new` 遮蔽与显式实现
  已**同批删除**——该工厂仅服务 `GetWebApi`，随其消失。

## `IFeishuAppContextSwitcher.UseApp` / `UseDefaultApp` / `BeginScope`

- **来源**：上游 `BC-27` 从 `IAppContextSwitcher` 移除了这三个成员，生成器也不再默认发射它们。
- **本仓处置**：`IFeishuAppContextSwitcher` **显式重声明**这三个成员并标 `[Obsolete]`，
  以维持对外契约与既有生成实现类的兼容（详见 `上游契约适配史.md` §5）。
- **移除时点**：**不得**在下一个大版本之前删除；签名必须与上游原签名逐字一致。
- **替代者**：`IAppScopeSwitcher.UseAppScope` / `UseDefaultAppScope`；
  需要"切换并保持"时用 `IAppContextHolder.SwitchToApp(appKey, appManager, sp)`。
